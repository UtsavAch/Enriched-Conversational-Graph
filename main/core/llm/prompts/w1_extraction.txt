You extract structured metadata from a single turn of a conversation.

Given one question/answer pair, produce two things:

1. entities - the specific, named things this turn talks about. Think of them as
   the entries a careful reader would put in the index of a report about this
   conversation: people, organisations, places, named systems, products, tools,
   documents, events, and the domain's own named concepts.
   Allowed types for this conversation:
   {allowed_entity_types}

   NAME EACH ENTITY IN ITS CANONICAL FORM, so the same thing gets the same name
   in every turn:
   - The bare name, without arguments, values, or paths attached: a command or
     flag without its arguments ("--mem", not "--mem=32G"; "sbatch", not
     "sbatch job.sh"); a storage area by its name ("$HOME", not "~/envs/app").
   - A domain concept in its singular, capitalised form even when the text
     writes it in lowercase or plural ("Invoice", not "invoices").
   - A URL path or API route as the path alone, without the HTTP method
     ("/invoices/{{id}}", not "GET /invoices/{{id}}").

   DO NOT EXTRACT:
   - generic words, even technical ones: "API", "HTTP", "database", "CPU",
     "GPU", "server", "the schema", "the pipeline";
   - field, attribute or column names ("created_at", "customer_id");
   - HTTP methods, status codes, error states or log values on their own
     ("POST", "404", "OUT_OF_MEMORY");
   - plain numbers, amounts and settings ("32G", "€500", "3 retries"), unless
     the turn treats the quantity itself as a named thing the conversation
     keeps coming back to (e.g. "the monthly budget");
   - incidental file names and shell snippets quoted in passing.
   When unsure, leave it out: a missing minor entity costs less than noise.

   If an entity clearly doesn't fit any allowed type - not just an awkward
   fit, genuinely none of them describe it - use "propose:<short_label>"
   instead. Use this rarely: prefer an existing type whenever one reasonably
   applies, and never propose a type that's just a rewording of one already
   allowed. Never use "propose:other" - "other" is already allowed.

2. speech_act - the discourse function of the USER's question turn. Choose
   exactly one of:
   factual_question, clarification_request, decision, suggestion, feedback,
   correction, follow_up, agreement, disagreement, information, request.

Note: the answer may contain bracketed markers like [N_3] pointing back to an
earlier interaction. These are citation markers — never extract a bracketed ID
as an entity, and ignore them when judging the speech act.

Return strict JSON only, with no preamble and no markdown fences:
{{"entities": [{{"name": "<canonical name>", "type": "<an allowed type, or propose:<label>>"}}, ...],
  "speech_act": "<one of the values above>"}}

If there are no entities, return an empty list. Do not invent entities that are
not present in the text.

FEW-SHOT EXAMPLES (the allowed types in these examples are illustrative):

Q: "Our community garden association wants to apply for the city's GreenSpaces
    grant. Who decides, and by when?"
A: "The Parks Department reviews GreenSpaces applications; this year's deadline
    is 15 March. Maria, as treasurer, should sign the budget sheet."
→ {{"entities": [{{"name": "GreenSpaces grant", "type": "document"}}, {{"name": "Parks Department", "type": "organization"}}, {{"name": "Maria", "type": "person"}}], "speech_act": "factual_question"}}
("15 March" is a date and "budget sheet" a generic noun - neither is extracted.)

Q: "The podcast feed shows old episodes. Should I re-run `ffmpeg -i ep12.wav
    -b:a 128k ep12.mp3` and then POST to /feeds/{{id}}/refresh?"
A: "Yes: re-encode with ffmpeg, then call /feeds/{{id}}/refresh on the Buzzsprout
    API [N_4]. The feed's updated_at field should change within a minute."
→ {{"entities": [{{"name": "ffmpeg", "type": "tool"}}, {{"name": "/feeds/{{id}}/refresh", "type": "propose:endpoint"}}, {{"name": "Buzzsprout", "type": "system"}}], "speech_act": "request"}}
(the full ffmpeg command, the file names, "128k", "POST", "API", the updated_at
field and the [N_4] citation are all left out; the route is named without its
HTTP method.)

Q: "When you said the volunteers' rota is still open - is that settled yet, or
    should I flag it?"
A: "Not settled yet. I'd flag it as an open question for the next meeting."
→ {{"entities": [], "speech_act": "clarification_request"}}
