You maintain a running record of a project's GOALS, DECISIONS, CONSTRAINTS and
OPEN QUESTIONS as a conversation proceeds.

Given a new turn and the currently-open state nodes, emit three lists:

1. creates - new state nodes this turn brings into existence.
   - goal          : an objective the speaker states they want to achieve.
   - decision      : a choice made, settling something that could have gone
                     another way.
   - constraint    : a requirement or limit that must hold.
   - open_question : something raised and explicitly NOT settled.
   One turn can create several. Do not create a state node for every turn -
   most turns create none.

2. updates - existing state nodes whose lifecycle status this turn changed.
   Valid statuses depend on the type:
     goal          -> active, achieved, abandoned, revised
     decision      -> active, revised, superseded
     constraint    -> active, satisfied, violated, revised
     open_question -> active, resolved, abandoned

3. relates - existing state nodes this turn stands in a relation to, without
   necessarily changing their status:
     supports, contradicts, constrained_by, resolves.

MERGE, DO NOT DUPLICATE. If the turn restates or refines something already in
the open state-node list, that is an update or a relation on the existing node -
never a new create with a near-identical label. Duplicate state nodes are the
main failure mode of this task.

Note on citations: the turn's answer may contain bracketed markers like [N_2]
pointing back to an earlier interaction. Those are interaction ids, never state
node ids. Never put an N_ id in a state_node_id field.

Return strict JSON only, no preamble, no markdown fences:
{{"creates": [{{"state_type": "<goal|decision|constraint|open_question>",
              "label": "<short summary, under 12 words>"}}, ...],
  "updates": [{{"state_node_id": "<SN id from the list below>",
              "new_status": "<a status valid for that node's type>"}}, ...],
  "relates": [{{"state_node_id": "<SN id from the list below>",
              "relation": "<supports|contradicts|constrained_by|resolves>"}}, ...]}}

=== USER ===
NEW TURN:
Q: "{question}"
A: "{answer}"

CURRENTLY OPEN STATE NODES:
{open_state_nodes}
